# Google Colab: standalone notebook compatibility

This repository contains both independently runnable educational notebooks and multi-stage examples. When opening a **single** `.ipynb` file in Colab, only that notebook is present in the Colab workspace by default; GitHub does not automatically copy sibling `.py` files or datasets into it.

## What was fixed

The notebooks changed in this PR now prepare their repository working directory when running in Google Colab, and install selected missing Python dependencies (such as `tiktoken`, `safetensors`, and `transformers`) where needed. Chapter 5's alternative GPT-2 weight-loading examples use the repository's shared `GPTModel` and generation functions rather than assuming `llms_from_scratch.ch04` and `llms_from_scratch.ch05` are preinstalled. The extension-tokenizer example obtains pretrained weights from the public Hugging Face model `rasbt/gpt2-from-scratch-pytorch`. The IMDb scikit-learn example runs the included dataset-preparation script if the CSVs do not yet exist.

**Open the notebook from the updated branch (or after merging this PR into main)** and execute cells from top to bottom. A Colab GPU is useful for training, but it does not make every very large or gated model fit into 16 GB.

## What cannot be downloaded from Git

Some notebooks depend on **trained checkpoints generated by an earlier exercise** rather than checked-in source files. These files are not included in the repository and cannot be recovered merely by cloning it:

| Notebook | Missing artifact | How to obtain |
|---|---|---|
| `ch05/01_main-chapter-code/exercise-solutions.ipynb` (some exercises) | `model.pth`, `model_and_optimizer.pth` | Run the relevant checkpoint-saving cell in Chapter 5; copy/upload the output |
| `ch06/01_main-chapter-code/load-finetuned-model.ipynb` | `review_classifier.pth` | Run and save the Chapter 6 classifier fine-tuning |
| `ch07/01_main-chapter-code/load-finetuned-model.ipynb` | `gpt2-medium355M-sft.pth` | Run and save the Chapter 7 SFT exercise |
| `ch07/04_preference-tuning-with-dpo/dpo-from-scratch.ipynb` | `gpt2-medium355M-sft.pth` | Copy the Chapter 7 SFT checkpoint to this notebook's working directory |

In Colab, you can upload the artifact with `from google.colab import files; files.upload()`, copy it from Google Drive, or change the filename to the actual checkpoint location.

Other **external prerequisites** are not local-file bugs: models gated behind Hugging Face/Meta authorization need credentials, OpenAI API examples need an API key, Ollama examples require a reachable Ollama server, and multi-billion-parameter experiments can exceed T4 16 GB. They are intentionally **not** automatically installed, authenticated or launched.

## Verification and limitations

- Static review: patched notebook JSON remains parseable and cross-chapter imports have been redirected where applicable.
- The notebook bootstraps were **not all executed end-to-end on Google Colab**. Weight downloads can depend on network access and library version compatibility, and training examples depend on GPU resources.
- The quick `Colab bootstrap` code fetches repository files into `/content/LLMs-from-scratch`, then switches to the notebook's own directory. Once the repository is cloned, a Colab runtime restart or deletion of the clone is needed to force a fresh clone.
